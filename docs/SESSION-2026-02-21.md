**Solutions**:
- Removed `espeak-phonemize` from requirements.txt
- Upgraded pip/setuptools before installing dependencies
- Installed chatterbox-tts with `--no-deps` to avoid version conflicts
- Base PyTorch image already has compatible numpy 2.1.0

### 3. SSL Certificate Workaround
**Issue**: Model downloads failed with SSL verification errors (corporate/academic environment)

**Solution**: Monkey-patched `requests` module to disable SSL verification for model downloads:
```python
# Disable SSL verification for downloads
import warnings
from urllib3.exceptions import InsecureRequestWarning
warnings.simplefilter("ignore", InsecureRequestWarning)

original_request = requests.Session.request
def patched_request(self, *args, **kwargs):
    kwargs["verify"] = False
    return original_request(self, *args, **kwargs)
requests.Session.request = patched_request
```

## Key Learnings

1. **Python 3.12 Compatibility**: PyTorch 26.01 uses Python 3.12, which removed `distutils` and has setuptools compatibility issues. Always upgrade setuptools first.

2. **Dependency Conflicts**: When base image has newer versions (numpy 2.1.0) but package requires older (numpy <1.26.0), use `--no-deps` to skip strict version checks.

3. **SSL in Corporate Environments**: Academic/corporate networks often have SSL inspection. Need workarounds for HTTPS downloads.

4. **Devcontainer Architecture**: Clean separation between immutable base image and project-specific setup enables portability across environments (local dev, DGX, cloud).

5. **Git Worktrees in Containers**: Worktrees have special `.git` file structure that doesn't work inside containers. Initialize submodules on host before mounting.
